# Item Intelligence v1.2 — Amands Sense integration

## Product boundary

Amands Sense remains an optional renderer for world-loot attention. Item Intelligence owns the decision. The integration must not edit `AmandsSense.dll`, its assets, `Items.json`, or the user's Sense configuration. When Sense is absent or the integration is disabled, Item Intelligence performs no Sense-specific steady-state work.

The installed Sense 3.1.0 build exposes item classification and color concepts (`GetSenseItemType`, `GetItemColor`, `SenseItemColor`, `currentColor`, and `outlineColor`). The preferred implementation is a small reflection/Harmony adapter loaded only when `xyz.drakia.Sense` is present. It supplies an Item Intelligence decision after Sense has resolved the native item and preserves Sense behavior when II has no override.

Sense remains the sole owner of its existing rare/valuable, yellow/purple category, wishlist-heart, quest-item, container, body, and exfil presentation. Item Intelligence must not recolor or replace those icons merely to make the palettes uniform. It adds a presentation only for an unmet II requirement and yields back to the unmodified Sense result for every other item.

## Added requirement indicators

An Item Intelligence requirement indicator means: **pick up and keep this item now for the stated requirement**. It does not replace Sense's red wishlist heart; that heart keeps its existing favorite-item meaning.

It is shown only while Item Intelligence has an unfilled consumptive requirement. `Enough` and `Not Needed` do not receive the keep icon. They may still use Sense's ordinary value/category presentation when the user enables it.

The world-loot decision uses the same immutable allocation as the inventory card:

1. active FIR-only quest deficit;
2. active any-item quest deficit;
3. current incomplete hideout level;
4. future FIR-only quest deficit;
5. future any-item quest deficit.

FIR loot is assigned to FIR-only deficits first. One unit is reserved once. Picking up a stack reduces the raid-local deficit by its stack count so later copies do not remain falsely urgent.

## Visual hierarchy

The icon shape identifies the requirement source. Active and future quests may reuse an icon already owned and rendered by Sense when its public/runtime presentation allows this without copying the asset. Hideout and any missing distinction use small original Item Intelligence icons or procedural shapes shipped only with Item Intelligence.

The icon color communicates the highest-priority unmet reason. Its outline may communicate a second simultaneous reason. Icon, outline, and text colors are independent channels and do not need to match. Default text remains neutral for readability; only the remaining count may inherit the primary requirement color.

| State | Primary presentation | Secondary outline |
| --- | --- | --- |
| Active quest missing | quest indicator, configurable active color | hideout or future color |
| Current hideout missing | original II hideout indicator, configurable hideout color | future color |
| Future quest missing | distinct future-quest indicator, configurable future color | none |
| Enough | no II override | unchanged native Sense result |
| Not Needed | no II override | unchanged native Sense result |
| Data unavailable | no II override | unchanged native Sense result |

The exact colors remain configurable. The semantic ordering does not depend on color, and optional short text can state `Quest`, `Hideout`, or `Future` plus the remaining count.

Generic craft/barter relevance is excluded from the default requirement signal. A recipe merely accepting an item does not define how many the player intends to retain. A later opt-in low-priority indicator may show craft/barter relevance without using a quest/hideout icon. Existing Sense high-value and category highlighting remains unchanged.

## Runtime behavior

- Resolve by template id and stack count; never classify by localized item name.
- Treat loose raid loot as FIR where EFT reports FIR status.
- Maintain a raid-local reservation ledger updated from pickup, drop, consume, and inventory-change events.
- Reset the ledger at raid start/end and when the authoritative Item Intelligence snapshot changes.
- Do not poll the world or rebuild requirement indexes per frame.
- Cache the final Sense presentation by template id, FIR state, stack count bucket, and Item Intelligence snapshot revision.
- Preserve native Sense rare/valuable icons, yellow/purple categories, red wishlist heart, quest-item, container, body, exfil, and category behavior outside unmet II requirement overrides.

## F12 controls

- `Amands Sense Integration`
- `Required Items`
- `Secondary Reason Outline`
- `Remaining Count Text`
- `Craft / Barter Relevance` (off by default)
- independent icon, outline, remaining-count, active-quest, hideout, and future-quest colors

All controls belong to Item Intelligence. No automatic rewrite of the Sense configuration is permitted.

## Acceptance gates

1. Deterministic mapping tests cover every state and overlapping-reason priority.
2. Raid-local allocation tests prove FIR-first and no double counting across successive pickups.
3. With integration disabled, no Sense types are reflected or patched.
4. With Sense absent, Item Intelligence loads normally.
5. Physical testing verifies loose items, containers, stacked loot, pickup updates, drop updates, and raid reset.
6. Existing Sense rare/valuable colors and icons, yellow/purple categories, and red wishlist heart are byte-for-byte/config-for-config untouched and visually unchanged.
