# Economy Admiral runtime gate

Physical acceptance target: **SPT 4.1.3**, current target mod stack, exact `economy-admiral-candidate` from PR #196.

## Audit / Normal gate

Install the Actions candidate under `SPT_Runtime/user/mods/Economy Admiral/`, leave `mode=Audit` / `preset=Normal`, start SPT and allow all startup/PostLoad callbacks to finish. Then run the packaged `Validate-Runtime.ps1`.

PASS requires:

- runtime evidence schema v3;
- exact packaged build identity;
- pristine baseline captured at priority `1` before normal mod callbacks;
- positive pristine quest count;
- exact provenance partition with non-negative `added / modified / unchanged / removed` counts;
- `modified + unchanged + removed = pristine`;
- `added + modified + unchanged = final`;
- **9/9 working reports** plus runtime manifest;
- `PristineStartupSnapshot` benchmark source in primary, utility, progression and constraint reports;
- provenance delta exactly consistent with manifest counts;
- enforcement plan schema v4 / mutation-eligibility policy v2;
- `PristineUnchanged` candidates protected;
- `PristineModified` reward eligibility limited to reward dimensions actually proven changed versus pristine;
- unknown provenance blocked;
- every `AutomaticMutationAllowed=false` and every `ProposedMutation=null`;
- identical before/after final-DB fingerprints;
- quest fingerprint coverage includes trader identity, restartability, full conditions and full rewards;
- fingerprint also covers item identities, handbook prices and trader assort items/barter/loyalty mappings;
- `DatabaseUnchangedAcrossPipeline=true`;
- `RuntimeGatePassed=true`;
- zero mutations;
- no selected composite policy;
- `economy-admiral-primary-parity.json` exists from the same run;
- primary parity schema v1;
- `AllMatched=true`;
- `QuestRowsMatch=true`;
- `AcquisitionMatches=true`;
- `BenchmarkMatches=true`;
- `Mismatches` is empty.

The parity gate is deliberately independent from the existing zero-mutation/provenance gate. A clean fingerprint does **not** prove source-correct accounting, and source-correct accounting does **not** replace the fingerprint gate. Both must pass before #139 may remove the legacy correction overlays.

## Primary parity inspection

Open `reports/economy-admiral-primary-parity.json` from the same startup run. The only acceptable architecture-removal result is:

```text
SchemaVersion = 1
QuestRowsMatch = true
AcquisitionMatches = true
BenchmarkMatches = true
AllMatched = true
Mismatches = []
```

If `AllMatched=false`, do not remove any correction service. Retain the full parity report because its bounded mismatch list identifies the first source-correct differences that must be resolved.

## Admiral Trader cross-mod evidence

When Admiral Trader is installed in the tested stack, also retain the same-run Admiral Trader adapter/source-pressure reports generated by the candidate. They are observational evidence and do not change the 9-report runtime manifest count. Confirm there is no adapter exception in the server log and that installed Admiral Trader evidence is resolved through its explicit adapter rather than inferred from LL1 alone.

## Off gate

After Audit passes: stop SPT, set `mode=Off`, remove/move existing reports, start SPT again, and confirm Economy Admiral generates no new reports.

Retain:
